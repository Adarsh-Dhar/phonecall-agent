# Phone Agent — Technical Documentation (Free-Tier MVP)

## 1. Overview

**Product name:** Phone Agent (working title)
**One-line pitch:** An AI agent that makes real outbound phone calls on a user's behalf to handle everyday admin tasks — booking appointments, calling customer service, following up on bills or deliveries — and only pings the user when a real decision is needed.

**Track fit:** Everyday Agents — solves a real, recurring personal-admin pain point, runs autonomously, and surfaces to the human only at decision points.

**MVP goal:** Prove the core loop — *user gives instruction → agent calls a real phone number → agent has a natural conversation → agent books/confirms something → agent reports back* — using entirely free-tier tools, with zero cost to build, test, and demo.

---

## 2. Problem Statement

Phone calls remain one of the last "un-automated" chores of daily life. Most people avoid or delay:

- Booking appointments (dentist, doctor, salon, car service)
- Calling customer service / support lines
- Following up on bills, deliveries, insurance claims, or paperwork
- Any transactional, live, real-time conversation

Existing AI voice products (Vapi, Retell, Bland, etc.) are overwhelmingly built for **businesses receiving inbound calls** (support lines, IVR replacement). Almost nothing is built for **consumers making outbound calls** on their own behalf. That's the gap this project targets.

---

## 3. User Flow (MVP Scope)

1. **Instruction** — User sends a short text instruction via a simple chat/app interface:
   > "Book me a dental cleaning next week, preferably Tuesday or Thursday afternoon."
2. **Context gathering** — Agent resolves the phone number to call (from a small contacts list for MVP) and checks the user's stated availability (hardcoded or simple calendar stub for MVP).
3. **Outbound call** — Agent places a real call via the telephony provider.
4. **Live conversation** — Agent listens (STT), reasons (LLM), and responds (TTS) in real time, handling typical back-and-forth (offering times, answering basic questions, confirming spelling of name, etc.).
5. **Outcome capture** — Agent extracts the result of the call (e.g., "Tuesday 3:00 PM confirmed") into structured data.
6. **Escalation (if needed)** — If the call hits a decision the agent isn't authorized to make (e.g., a price it wasn't told about, no matching time slot), it ends the call politely and asks the user via text.
7. **Summary** — Agent sends the user a short text summary of what happened and updates their calendar/notes.

**Explicitly out of scope for MVP:** payments over the phone, multi-call negotiation chains, voicemail navigation trees, real calendar integrations (Google Calendar can be a stretch goal), multi-user accounts, production-grade auth.

## 4. System Architecture

```
                ┌───────────────────────┐
                │   User (Text/App UI)   │
                └───────────┬────────────┘
                             │ instruction
                             ▼
                ┌───────────────────────┐
                │   Orchestrator Agent   │  (Strands Agents SDK)
                │  - parses instruction  │
                │  - plans call goal     │
                │  - holds memory/tools  │
                └──────┬─────────┬───────┘
                       │         │
        places call    │         │  reads/writes
                       ▼         ▼
          ┌─────────────────┐  ┌─────────────────┐
          │ Telephony Layer │  │  Tool Layer      │
          │ (Twilio /       │  │  - contacts store│
          │  Vapi/Retell/   │  │  - calendar stub │
          │  Bland)         │  │  - notes/summary │
          └───────┬─────────┘  └─────────────────┘
                  │  live audio stream
                  ▼
     ┌─────────────────────────────┐
     │  Real-time Voice Pipeline   │
     │  STT → LLM (Gemini 2.5      │
     │  Flash Native Audio Live)   │
     │  → TTS  (or native S2S)     │
     └───────────────┬─────────────┘
                      │ transcript + outcome
                      ▼
             ┌───────────────────┐
             │  Outcome Extractor │
             │  (LLM call, JSON   │
             │  structured output)│
             └─────────┬──────────┘
                        ▼
             ┌───────────────────┐
             │  Summary to User   │
             │  (text/app message)│
             └───────────────────┘
```

### 4.1 Core pipeline (per phone call)

```
Telephony (call audio) → Speech-to-Text → LLM "brain" → Text-to-Speech → back into call
```

Or, where supported, a **native speech-to-speech model** collapses STT/LLM/TTS into one real-time audio-in/audio-out loop, which is lower-latency and more natural. This is why Gemini's Live API (native audio dialog) is the recommended brain for the MVP.

## 5. Component Breakdown

| Layer | Purpose | Free-tier options | MVP pick |
|---|---|---|---|
| **Telephony** | Places/receives real phone calls, streams audio | Twilio (trial), Vapi (free credits), Retell AI (free credits), Bland AI (free credits) | Twilio free trial (well-documented, most flexible) or Vapi (fastest to prototype voice agents specifically) |
| **AI brain / reasoning + voice** | Understands conversation, decides what to say, generates speech | Gemini free tier, especially Live API models | **Gemini 2.5 Flash Native Audio Dialog (Live API)** |
| **Orchestration** | Manages tools, memory, multi-step reasoning, escalation logic | Strands Agents SDK (open source) | Strands Agents SDK |
| **Tools** | Give the agent capabilities beyond talking | Custom functions | Calendar lookup/update, contact lookup, send-summary-to-user, escalate-to-user |
| **User interface** | Where the user gives instructions and receives summaries | Simple web/chat app | Minimal chat UI (or even a CLI/Slack bot for hackathon demo) |
| **Storage** | Persist contacts, call logs, summaries | Free-tier DB | SQLite (local) or a free-tier hosted DB (e.g. Supabase free tier) for demo persistence |

---

## 6. Recommended Model: Gemini 2.5 Flash Native Audio Dialog (Live API)

- Supports **native audio dialog** — real-time, streaming, two-way voice conversation without a separate STT/TTS hop, which reduces latency and produces more natural turn-taking (interruptions, pauses, tone).
- Good free-tier rate limits for prototyping compared to alternatives.
- Fits the "brain" role in the pipeline directly, or can be paired with a lighter reasoning pass (e.g., a second LLM call) for structured tasks like extracting the final outcome into JSON after the call ends.

**Fallback pipeline** (if native audio proves unstable mid-call): use a modular STT → text LLM → TTS chain instead, which is easier to debug turn-by-turn but adds latency.

## 7. Tools the Agent Needs

Minimum tool set for MVP:

1. **`lookup_contact(name)`** — resolves a business/person to a phone number from a small stored contacts list.
2. **`get_user_preferences(task)`** — returns constraints the user gave (e.g., "Tuesday or Thursday afternoon").
3. **`check_calendar(date_range)`** — stubbed for MVP (hardcoded free/busy times), Google Calendar API as a stretch goal.
4. **`update_calendar(event)`** — writes the confirmed appointment to storage (or real calendar if stretch goal is done).
5. **`end_call(reason)`** — gracefully ends the live call.
6. **`escalate_to_user(question)`** — pings the user via text when a real decision is needed mid-flow (e.g., no matching slot, unexpected cost).
7. **`send_summary(result)`** — sends the final text summary to the user after the call.

## 8. Data Flow / Storage (MVP)

Simple structured record per task, e.g.:

```json
{
  "task_id": "abc123",
  "instruction": "Book a dental cleaning next week, Tue or Thu afternoon",
  "contact_called": "Bright Smile Dental",
  "phone_number": "+1-555-0100",
  "call_status": "completed",
  "transcript_summary": "Offered Tue 3pm and Thu 2pm, booked Tue 3pm",
  "outcome": {
    "booked": true,
    "date": "2026-08-25",
    "time": "15:00",
    "confirmation_note": "Bring insurance card"
  },
  "escalations": []
}
```

SQLite is sufficient for a hackathon demo; no paid database needed.

## 9. Can This Be Built at $0? Yes — Free-Tier Bill of Materials

| Resource | Free allowance | Enough for MVP? |
|---|---|---|
| Twilio trial account | ~$15 trial credit / roughly 75 minutes of voice calls, calls restricted to verified numbers | Yes — enough to demo several real calls to your own verified test numbers |
| Vapi / Retell AI / Bland AI | Free credits + a free trial phone number on signup | Yes — good alternative/backup to Twilio, some are purpose-built for voice agents so faster to prototype |
| Gemini API free tier | Generous free quota for development, includes Live API access | Yes — sufficient for iterative development and demo calls |
| Strands Agents SDK | Open source, no cost | Yes |
| Storage (SQLite) | Local, free | Yes |
| Hosting for demo | Free tiers of Render/Vercel/Railway, or just run locally during the hackathon demo | Yes |

**Constraint to plan around:** free telephony trials typically only let you call **verified phone numbers** (numbers you've confirmed you own/control). For a hackathon demo this is not a blocker — you demo by calling your own phone or a teammate's phone. It becomes a real cost only once you want to call arbitrary businesses at scale in production.

## 10. Build Order (Step-by-Step)

1. **Set up accounts** — Twilio (or Vapi) trial, Gemini API key, verify a test phone number.
2. **Hello-world call** — Get a basic outbound call working that plays a static TTS message. Confirms telephony + audio pipeline works end-to-end.
3. **Wire up Gemini Live API** — Replace static message with a live, two-way audio loop so the agent can hold a real conversation.
4. **Build the orchestrator** — Set up Strands Agents SDK with a system prompt describing the agent's role, constraints, and tone.
5. **Add tools** — Implement `lookup_contact`, `check_calendar` (stub), `update_calendar`, `escalate_to_user`, `send_summary`.
6. **Add escalation logic** — Explicit rule: if the call reaches a decision outside the given constraints, end the call and text the user instead of guessing.
7. **Add outcome extraction** — After the call ends, run a structured-output LLM pass on the transcript to fill in the JSON record.
8. **Build minimal UI** — A simple chat interface (or Slack/CLI for hackathon speed) where the user types the instruction and receives the summary.
9. **Test end-to-end with a real call** — Call your own verified number, play the "business" side yourself, confirm the whole loop works.
10. **Polish for demo** — Add a short scripted scenario (e.g., booking a haircut) that reliably shows the full flow live.

## 11. Example System Prompt (Draft)

```
You are a phone-calling assistant acting on behalf of {user_name}.
Your job on this call: {task_goal}
Constraints given by the user: {constraints}

Rules:
- Speak naturally and briefly, like a real person making a call.
- Stay strictly within the given constraints (e.g., only offered days/times).
- If the person on the call offers something outside your constraints
  (different price, no matching time, needs info you don't have),
  do not guess or agree — politely say you'll confirm and get back to them,
  then end the call and escalate to the user.
- Confirm all booked details out loud before ending the call
  (date, time, location, any preparation instructions).
- Keep a natural, polite, concise tone throughout.
```

## 12. Risks & Open Questions

- **Latency/naturalness of native audio dialog** under real call conditions (background noise, interruptions, hold music) — needs early testing.
- **Voicemail / IVR menus** — MVP should detect these and escalate rather than attempt to navigate them.
- **Legal/consent considerations** for call recording, which vary by region — worth a disclaimer step in the demo, not a blocker for a hackathon MVP.
- **Number verification limits** on free telephony trials — fine for demo, a real constraint for any post-hackathon rollout.

---

## 13. Why This Fits "Everyday Agents"

- Targets a genuine, common daily frustration rather than a novelty use case.
- Runs autonomously (places the call, holds the conversation) and only interrupts the user when a real decision is required — the core "agent" behavior the track is looking for.
- Fully buildable and demoable at $0 using existing free tiers, which matters for a time-boxed hackathon build.

## 14. Possible Stretch Goals (Post-MVP)

- Real Google Calendar integration instead of the stub.
- Multi-contact memory (agent remembers previously called businesses/preferences).
- Outbound call queue for multiple tasks in one session.
- Voice cloning / personalization of the agent's voice (with consent).
- Production telephony (paid numbers, higher call volume, non-verified numbers).
